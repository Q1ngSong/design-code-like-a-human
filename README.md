# design-code-like-a-human

凌晨四点,autoresearch 跑完了。早上你打开仓库:

> - `main` 上多了一串 message 相同的 commit
> - `train.py` 多了几条 `if` 分支
> - 根目录又出现一个 `metrics_final_v2.json`
> - 核心包开始 import `scripts/` 里的评测代码

每一处改动都能在 diff 里找到,但你不知道昨晚真正走的是哪条路径,
也不知道哪个结果对应哪次改动。

问题不是代码有没有 bug,是你得先重建现场才敢继续实验。
而重建现场这件事,经常比重写一遍还累。

**回头读代码时,你会卡在这几处:**

1. **结构混乱** —— 核心层反过来依赖脚本层。想复用核心逻辑,得先拆评测代码。相近逻辑还散在新函数和包装层里
2. **过度设计** —— 防御性分支越堆越多,这次实验的主线藏在几条都能跑的路径里
3. **注释不足** —— 函数没有说明,也没有角色。一个零调用者可能是入口,也可能是死代码
4. **缺一个说得清结构的工具** —— 「这个函数干嘛的」只能靠通读
5. **改动没有记录** —— 函数体改过了,git blame 说得清谁改的,说不清为什么改

**继续跑实验时,另一批问题会出现:**

6. **实验没有利用好 git** —— 调参全堆在主分支。同名 commit 分不清方向。指标和结论留在终端里,也对不上当时的代码
7. **中间文件不归档** —— 写盘路径散在每个写盘点上,结果也跟着散开
8. **并行实验没有隔离** —— 想同时跑两组,只能等,或者手动来回改配置

**过度设计的代码占据了我们脑中所有的带宽。**

## 这个项目做什么

一个给科研原型代码加工程纪律的 Claude Code 插件。
它按问题发生的时间,把处理方式分成两类。

**已经写下的代码,用十一条规则查。** 一条命令生成审计报告,定位到文件和行号:
零调用者、反向依赖、缺失的变更记录、写死的写盘路径、标成 `[一次性]` 却放错层的代码。
这些先由工具定位,不必靠人从头通读。是否处置,仍要结合上下文判断。

**正在写的那一刻,用六个技能管。** 技能按 Claude 正在做的事自动触发:
写代码前先找现成实现、写盘前先确定目录、跑实验前先开分支。
这些是习惯,规则替不了,但可以在动手那一刻提醒。

规则查的是**已经写下的代码**,技能管的是**正在写的那一刻** ——
同一个关切的两道闸,覆盖不同时间点。

报告长这样(路径、名称、条数都是举例):

```text
R1  零调用者 —— 大概率是死代码  (2)
  model/attention.py:84  build_legacy_mask  零调用者

D1  依赖方向违规 —— 内层引用外层,模块化崩坏  (1)
  core/model.py:12  import  [core] 依赖了 [scripts]

C1  改了已有函数却没留变更记录 —— 补一行「变更:」  (1)
  train.py:126  train_step  函数体已改但 docstring 里没加「变更:」行
```

它不检查算法正确性,不解决 bug,也不替你判断代码该不该留。
它只是让「看不懂自己的代码」这件事有据可查。

## 安装

先装 codegraph,图规则(R1/R2/R3/D1)依赖它的索引:

    npm i -g @colbymchenry/codegraph

再作为 Claude Code 插件安装本项目。**整体安装**,不要只取 `skills/` ——
技能要调用 `scripts/refresh.py`,`hooks/` 也需要注册。

装完就能用,不需要克隆本仓库、不需要往 PATH 里加东西。
技能自己知道脚本在插件内的什么位置。

## 在一个项目里启用

在**你自己的代码仓库**里:

    echo '{}' > .comment-standard.json

就这一步。索引由命令在第一次运行时自动建立，不用手工 `codegraph init`。

`.comment-standard.json` 的存在与否是总开关:没有它,hook 静默退出,
命令给出提示而不做任何事。

`codegraph.json` 由我们从 `codegraph` 段自动生成,**一处维护**,
别手改它 —— 每次刷新都会覆盖。

反过来,把配置里的 `codegraph` 段删掉**不会**删除已生成的 `codegraph.json`
(分不清它是我们生成的还是你自己写的),命令会提示它还在、不再受管理,
要清掉自己删。

完整配置(全部可选):

    {
      "layers": ["ovam", "scripts", "temp_scripts"],
      "vendored": ["sd15"],
      "output_roots": ["runs"],
      "codegraph": { "exclude": ["notebooks/"] }
    }

- `layers` 由核心到外围排序,依赖只能由外向内。不写就不做分层校验。
- `vendored` 复制进来的第三方代码(如官方 `sd15/`)。索引但不审注释;
  谁都能依赖它,它不能依赖你的代码。
- `output_roots` 实验输出区的目录名，列表。排除在索引与审计之外。默认 `["runs"]`。
- `codegraph` 索引范围的加减。只在某个目录大到拖慢索引时才需要。

**我们只校验你自己声明过的东西,不校验我们的偏好。**

### layers 怎么填

判据只有一条:**谁离不开谁**。

- **最内层** —— 拿掉它别的就跑不了,通常是同名于项目的包或放算法主体的目录
- **最外层** —— 拿掉它主体照常跑,临时脚本、探针
- **中间层** —— 调核心、又被外层调,评测和训练脚本

分不清就问自己:「拿掉 `scripts/`,`ovam/` 还能用吗?反过来呢?」

| 项目长这样 | 填什么 |
|---|---|
| 核心包 + 脚本 + 临时脚本 | `["ovam", "scripts", "temp_scripts"]` |
| 一个包 + 根上几个脚本 | `["<包名>"]`,根上的不分层、自动跳过 |
| 全平铺没有结构 | **别写**。分层是描述现状,不是强加结构 |
| 分不清中间层 | 先写两层,跑一轮看 D1 报什么再细分 |

**层不必覆盖所有目录**,没进任何层的路径跳过校验。**顺序写反比不写更糟** ——
会把正常依赖全报成违规,满屏 D1。拿不准就先只写最内层那一个。

不想自己判断的话,直接让 Claude 看一眼目录结构给建议 —— 审计技能里有同样的判据。

`codegraph` 段原样写进生成的 `codegraph.json`,用来控制索引范围。
通常不用写 —— codegraph 默认索引除 `.gitignore` 忽略之外的一切,够用。
只有某个目录大到拖慢索引时才配:

    { "codegraph": { "exclude": ["notebooks/", "legacy/"] } }

**注意 `include` 不是白名单**,它是"把被 gitignore 丢掉的源码拉回来"。
要限制索引范围只能用 `exclude` 列出不要的。

## 实验输出往哪存

`saving-experiment-outputs` 技能在写任何产生文件的脚本前介入,先问清楚
「这次要回答什么、服务论文哪一节、这组变的是什么」,答案直接变成路径:

    out = Path("runs") / "ablation_study" / "lora_rank" / f"rank{rank}_lr{lr}"
    out.mkdir(parents=True, exist_ok=True)

两行,不 import 任何工具。**不提供 `save_root` 之类的辅助模块** ——
做过,385 行防一个打字错误,还逼着全项目改用 `python -m` 跑,已删除。

## 怎么用

**装完插件、在项目根放一个 `.comment-standard.json` 之后,就不用再记什么了。**
技能会按你在做的事自动触发:

| 你在做什么 | 触发的技能 | 它做什么 |
|---|---|---|
| 让 Claude 写或改代码 | `writing-minimal-code` | 先查代码库里有没有现成的,再决定写不写 |
| 写 Python 函数 | `writing-python-comments` | 按标准写 docstring:摘要 + 角色标记 + Args/Returns |
| 写会存文件的脚本 | `saving-experiment-outputs` | 动手前先说好输出存哪儿 |
| 开始一组调参实验 | `running-experiments-on-branches` | 开分支跑,别在主分支上堆 commit |
| 一次实验跑完 | `recording-experiment-results` | 往 CSV 里记一行再跑下一次 |
| 功能跑通了想清理 | `auditing-code-comments` | 跑十一条规则,出一份报告 |

### 想主动触发就直接说

技能是按语义匹配的,用大白话就行:

    审计一下这个项目的代码

    这次实验的结果存哪儿?

    这组调参开个分支吧

    帮我把这个函数的注释补上

### 报告在哪

每次审计都在项目的 `.codegraph/` 下生成两份:

    .codegraph/audit.md      给人看,概览表 + 每条规则一张定位表
    .codegraph/audit.json    给 Claude 看,结构化数据

`audit.md` 可以直接打开。Claude 汇报时也会把路径给你。

### 手动跑(可选)

想脱离 Claude 自己跑,或者接进 CI:

    python3 <插件目录>/scripts/refresh.py <你的项目>

插件目录在 `~/.claude/plugins/cache/` 下,具体路径问 Claude 或者
`find ~/.claude/plugins -name refresh.py`。

退出码:**0 表示已执行的检查没有产出 finding** —— 没建索引时四条图规则不跑,
这时的 0 不等于全部合规;1 有 finding;2 项目未启用或配置损坏。

**不要单独运行 `codegraph sync`。** 它会把变动文件在索引里的记录整个删掉重建,
清空回填结果,注释会从索引里静默消失 —— 必须走上面这条命令。

## 十一条规则

| 规则 | 判定 | 来源 |
|---|---|---|
| R0 | 缺 docstring 或角色标记 | 读源码 |
| R1 | 零调用者(最外层与 `[一次性]` 豁免) | 索引 |
| R2 | `[一次性]` 不在最外层 | 索引 + `layers` |
| R3 | 主线调用旁支 | 索引 |
| R4 | `def` 那一行有的参数,Args 里没写 | 读源码 |
| R5 | 有返回值但缺 Returns | 读源码 |
| R6 | Args 里写了 `def` 那一行没有的参数 | 读源码 |
| D1 | 内层引用外层 | 索引 + `layers` |
| D2 | 输出区存在但未被 .gitignore 忽略 | 文件系统 |
| D3 | 写盘点写死了输出路径 | AST |
| C1 | 改了已有函数却没加 `变更:` 行 | 比 git |

R3、D1、C1 报出来时先判断再动手 —— R3 问「本次实验用得到它吗」，
D1 说「核心层依赖了脚本层」，C1 要分清改的是别人依赖的东西还是只动了内部。
它们和其余七条一样计入不合规、影响退出码,只是处置需要人的判断。
处置指引见 `skills/auditing-code-comments/SKILL.md`。

## 技能

| 技能 | 什么时候用 | 覆盖痛点 |
|---|---|---|
| `writing-minimal-code` | 写新代码或改既有代码前 | 1、2、5 |
| `writing-python-comments` | 写或改 Python 函数时 | 3、5 |
| `auditing-code-comments` | 功能跑通后、提交前 | 1、2、3 |
| `saving-experiment-outputs` | 写任何会写盘的脚本前 | 7 |
| `recording-experiment-results` | 一次实验跑完,下一次开始前 | 6 |
| `running-experiments-on-branches` | 开始一组实验或调参时 | 6、8 |

`writing-minimal-code` 是一条四道决策流：该不该存在 → 能不能改现有的 →
新写的话代码从哪来 → 写成什么样。

它的两个目标是让读代码的人负担最小、让改动总量最小，而这两件事经常被搞反：
为了「不动旧代码」不断新加函数和包装层，不是改动变小了，是换个地方堆着。
改动大小按 diff 算，不按碰没碰旧文件算。

它同时列出**不能为了简洁删掉**的几类代码：随机种子、train/test 边界、
数值稳定性处理、防数据丢失的错误处理。科研代码里一段看着多余的逻辑，
可能正是当初调出那个数的原因，删掉之后数变了还不报错。

后三个是习惯，不是流程：写盘前说好存哪儿、跑完先记再跑下一次、
实验别在主分支上跑。技能里给的目录形状、CSV 列名、分支命名都是模板，
项目有自己的习惯就跟着它走。

## 规范本身

**规范就写在技能里**,`skills/` 下每个 `SKILL.md` 都是可直接读的完整规则,
不需要另外查文档。

每条机械规则背后都有一个 codegraph 的实测行为撑着,不是拍脑袋定的。
其中三条直接决定了工具的形状:

- codegraph 全语言统一读「前置注释」,**Python 的体内 docstring 捕获不到** ——
  所以要回填
- `sync` 会把整个文件在索引里的记录删掉重建,**回填的注释被清空,记录的编号也会变** ——
  所以不能旁挂 sidecar 表,只能每次重算
- 全文检索把连续的汉字当成一个整体、只能从头匹配，**中文关键词埋在词组中段就搜不到** ——
  所以摘要行要保留英文术语、关键词打头

设计文档、实施计划与调研笔记留在本地 `docs/`,不入库 —— 那是推演过程,
不是 plugin 的组成部分。

## 改规则之后

拿一个真实项目跑一遍,看漏报与误报:

    python3 scripts/refresh.py <项目>

规则里有几处不显眼的陷阱,改动时留意:

- SQLite 的 `LIKE` 中 `_` 是单字符通配符。过滤 `__init__` 这类名字必须写
  `NOT LIKE '\_\_%' ESCAPE '\'`,否则会滤掉**每一个**函数,规则静默失效
- `ast.walk` 会走进嵌套函数。判断"本函数有没有返回值"要自己走栈并跳过
  嵌套定义,否则内层的 `return` 会算到外层头上
- git 返回的是**仓库根**相对路径。项目根是仓库子目录时(monorepo)必须用
  `--relative` 与 `--show-prefix` 换算
- 目录匹配按路径段比,不按字符串前缀。`runs_archive/` 不算忽略了 `runs/`

## 已知限制

- 只支持 Python。图规则(R1/R2/R3/D1)天然跨语言,读源码的那几条要为每种语言补解析器。
- codegraph 不跟踪 `import X as Y` 别名,只通过别名到达的函数会被 R1 误报。
- 模块级 docstring 不回填。
