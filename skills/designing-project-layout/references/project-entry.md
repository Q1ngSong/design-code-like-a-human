# 项目入口：PROJECT.md

项目根上的 `PROJECT.md` 是**给 Agent 看的项目说明**，`README.md` 是给人看的。
两边写的是同一个项目，但不是同一件事：README 说怎么装、怎么用、方法是什么；
PROJECT.md 说主体代码在哪、怎么跑一次、这个项目有哪些规矩和边界。
Agent 不需要安装教程，人不需要知道分支怎么命名。

分开写是因为混着写两边都不好用：README 里塞分支命名，人读到一半问这跟我有什么关系；
PROJECT.md 里塞安装步骤，Agent 每次会话都要跳过一屏。

## 模板

    # <项目名> —— 给 Agent 的项目说明

    ## 在研究什么
    两三行：要回答的问题，现在押的路线。

    ## 代码
    主体在 `<核心目录>/`，做的是什么。
    功能脚本：`<功能脚本目录>/`，做的是什么。
    实验脚本目录：`<实验脚本目录>/`，做的是什么。
    分层、输出区、第三方代码的声明在 `.comment-standard.json`。

    ## 这个项目的规矩
    只写和插件默认不一样的地方；一样的不写。

    ## 输出结果与结论
    输出结果在`<输出结果目录>/`（可能不止一个），各个目录都是什么作用。
    当前结论看 `experiments/README.md`，每次尝试看组 CSV，
    谁基于谁看谱系页（`visualizing-experiment-lineage` 生成）。

## 两条让它不烂掉的规则

**状态一律不写**，只留最后那一节指路。当前跑到哪、上一次结论是什么、下一步打算试什么，
更新频率是「每次尝试」；这份文件的其余内容更新频率是「整个项目一两次」。
放在一个文件里，快的那部分会拖着慢的一起过期，而且没人能一眼看出哪几行已经不对了。
状态本来就有家：CSV 记每次尝试，组 README 记每组结论，`experiments/README.md` 记各部分现状，
git 和谱系页记谁基于谁。

**规矩只写例外。** 分支怎么开、记录怎么记、输出放哪，插件的技能已经告诉 Agent 了，
这里重复一遍只会多一处要同步的副本。这一节只记这个项目和默认不一样的地方——
输出根不叫 `outputs`、记录目录大小写不同、某个目录不许碰。没有例外就写「无」。

判断某句话该不该写进来，问一句：Agent 能不能从代码、记录或插件的规矩里推出来。
推得出来就别写。推不出来的只有三类：这个项目要回答什么、主体代码的分工、明确排除过的方向。

## 谁写、什么时候写

**新项目**：拟目录结构时连同 `layers` 建议值一起给出骨架。「在研究什么」和「边界」
只有用户知道，有人在场就问一句，问到什么写什么；无人值守时把这两节留空并在记录里
说明留空的原因，不替用户编研究目标。

**已有项目**：随时可以补，同一份模板，不需要先整理目录。

**什么时候改**：路线变了、边界变了、主体代码的分工变了。开组、跑完一次、收尾合并
都不改它——那些是状态。判据要改，写明改之前是什么、为什么改；不写就等于把标准
挪到结果那边去了。

**谁读**：每次会话开始时 hook 会提示先读它。开一组新实验前，
`running-experiments-on-branches` 会核对「边界」一节，免得又跑一遍排除过的方向。
