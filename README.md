# design-code-like-a-human

凌晨四点,autoresearch 跑完了。早上你打开仓库:

> - `main` 上多了一串 message 相同的 commit
> - `train.py` 多了几条 `if` 分支
> - 根目录又出现一个 `metrics_final_v2.json`
> - 核心包开始 import `scripts/` 里的评测代码

每一处改动都能在 diff 里找到,但你不知道昨晚真正走的是哪条路径,
也不知道哪个结果对应哪次改动。

问题不是代码有没有 bug,是你得先重建现场才敢继续实验。
而重建现场这件事,经常比重写一遍还累。

**回头读代码时,你会卡在这几处:**

1. **结构混乱** —— 核心层反过来依赖脚本层。想复用核心逻辑,得先拆评测代码。相近逻辑还散在新函数和包装层里
2. **过度设计** —— 防御性分支越堆越多,这次实验的主线藏在几条都能跑的路径里
3. **注释不足** —— 函数没有说明,也没有角色。一个零调用者可能是入口,也可能是死代码
4. **缺一个说得清结构的工具** —— 「这个函数干嘛的」只能靠通读
5. **改动没有记录** —— 函数体改过了,git blame 说得清谁改的,说不清为什么改

**继续跑实验时,另一批问题会出现:**

6. **实验没有利用好 git** —— 调参全堆在主分支。同名 commit 分不清方向。指标和结论留在终端里,也对不上当时的代码
7. **中间文件不归档** —— 写盘路径散在每个写盘点上,结果也跟着散开
8. **并行实验没有隔离** —— 想同时跑两组,只能等,或者手动来回改配置

**过度设计的代码占据了我们脑中所有的带宽。**

## 这个项目做什么

一个给科研原型代码加工程纪律的 Claude Code / Codex 插件。
它按问题发生的时间,把处理方式分成两类。

**已经写下的代码,用审计规则查。** 一条命令生成审计报告,定位到文件和行号:
零调用者、反向依赖、缺失的变更记录、写死的写盘路径、标成 `[一次性]` 却放错层的代码。
这些先由工具定位,不必靠人从头通读。是否处置,仍要结合上下文判断。

**正在写的那一刻,用技能管。** 技能按 Claude 正在做的事自动触发:
写代码前先找现成实现、写盘前先确定目录、跑实验前先开分支。
这些是习惯,规则替不了,但可以在动手那一刻提醒。

规则查的是**已经写下的代码**,技能管的是**正在写的那一刻** ——
同一个关切的两道闸,覆盖不同时间点。

报告长这样(路径、名称、条数都是举例):

```text
R1  零调用者 —— 大概率是死代码  (2)
  model/attention.py:84  build_legacy_mask  零调用者

D1  依赖方向违规 —— 内层引用外层,模块化崩坏  (1)
  core/model.py:12  import  [core] 依赖了 [scripts]

C1  改了已有函数却没留变更记录 —— 补一行「变更:」  (1)
  train.py:126  train_step  函数体已改但 docstring 里没加「变更:」行
```

它不检查算法正确性,不解决 bug,也不替你判断代码该不该留。
它只是让「看不懂自己的代码」这件事有据可查。

## 安装

先装 codegraph,图规则(R1/R2/R3/D1)依赖它的索引:

    npm i -g @colbymchenry/codegraph

再作为 Claude Code 插件安装本项目。**整体安装**,不要只取 `skills/` ——
技能要调用 `scripts/refresh.py`,`hooks/` 也需要注册。

装完就能用,不需要克隆本仓库、不需要往 PATH 里加东西。
技能自己知道脚本在插件内的什么位置。

## 在一个项目里启用

在**你自己的代码仓库**里:

    echo '{}' > .comment-standard.json

就这一步。索引由命令在第一次运行时自动建立，不用手工 `codegraph init`。

`.comment-standard.json` 的存在与否是总开关:没有它,hook 静默退出,
命令给出提示而不做任何事。

`codegraph.json` 由我们从 `codegraph` 段自动生成,**一处维护**,
别手改它 —— 每次刷新都会覆盖。

反过来,把配置里的 `codegraph` 段删掉**不会**删除已生成的 `codegraph.json`
(分不清它是我们生成的还是你自己写的),命令会提示它还在、不再受管理,
要清掉自己删。

完整配置(全部可选):

    {
      "layers": ["ovam", "scripts", "temp_scripts"],
      "vendored": ["sd15"],
      "output_roots": ["runs"],
      "codegraph": { "exclude": ["notebooks/"] }
    }

一层可以放多个平级目录，任何一层都行：`[["ovam","erase"], ["scripts_sd15","scripts_sdxl"], "temp_scripts"]` 表示两个核心包平级、两个脚本目录平级，同层互通，内层不依赖外层。

- `layers` 由核心到外围排序,依赖只能由外向内。不写就不做分层校验。
- `vendored` 复制进来的第三方代码(如官方 `sd15/`)。索引但不审注释;
  谁都能依赖它,它不能依赖你的代码。
- `output_roots` 实验输出区的目录名，列表。排除在审计之外。默认 `["runs"]`。
- `codegraph` 索引范围的加减。只在某个目录大到拖慢索引时才需要。

**我们只校验你自己声明过的东西,不校验我们的偏好。**

### layers 怎么填

判据只有一条:**谁离不开谁**。

- **最内层** —— 拿掉它别的就跑不了,通常是同名于项目的包或放算法主体的目录
- **最外层** —— 拿掉它主体照常跑,临时脚本、探针
- **中间层** —— 调核心、又被外层调,评测和训练脚本

分不清就问自己:「拿掉 `scripts/`,`ovam/` 还能用吗?反过来呢?」

| 项目长这样 | 填什么 |
|---|---|
| 核心包 + 脚本 + 临时脚本 | `["ovam", "scripts", "temp_scripts"]` |
| 一个包 + 根上几个脚本 | `["<包名>"]`,根上的不分层、自动跳过 |
| 全平铺没有结构 | **别写**。分层是描述现状,不是强加结构 |
| 分不清中间层 | 先写两层,跑一轮看 D1 报什么再细分 |

**层不必覆盖所有目录**,没进任何层的路径跳过校验。**顺序写反比不写更糟** ——
会把正常依赖全报成违规,满屏 D1。拿不准就先只写最内层那一个。

不想自己判断的话,直接让 Claude 看一眼目录结构给建议 —— `designing-project-layout` 技能管这个,新项目拟目录也是它。

`codegraph` 段原样写进生成的 `codegraph.json`,用来控制索引范围。
通常不用写 —— codegraph 默认索引除 `.gitignore` 忽略之外的一切,够用。
只有某个目录大到拖慢索引时才配:

    { "codegraph": { "exclude": ["notebooks/", "legacy/"] } }

**注意 `include` 不是白名单**,它是"把被 gitignore 丢掉的源码拉回来"。
要限制索引范围只能用 `exclude` 列出不要的。

## 实验输出往哪存

`saving-experiment-outputs` 技能在写任何产生文件的脚本前介入。项目已有输出目录的,
照现有习惯拼一个具体路径给用户确认一次;还没有的,才问「这次要回答什么、
服务论文哪一节、这组变的是什么」,答案直接变成路径:

    out = Path("runs") / "ablation_study" / "lora_rank" / f"rank{rank}_lr{lr}"
    out.mkdir(parents=True, exist_ok=True)

两行,不 import 任何工具。**不提供 `save_root` 之类的辅助模块** ——
做过,385 行防一个打字错误,还逼着全项目改用 `python -m` 跑,已删除。

## 怎么用

**装完插件、在项目根放一个 `.comment-standard.json` 之后,就不用再记什么了。**
技能会按你在做的事自动触发:

插件简称 **DCLH**。在 Codex、Claude Code 等支持 Agent Skills 的宿主中，
安装并启用插件后，统一用自然语言指定简称和任务：

    dclh 审计这个项目的注释

    用 dclh 帮我规划一组调参实验

    dclh 按现有计划继续实验

短入口定义在 [skills/dclh/SKILL.md](skills/dclh/SKILL.md) 的 YAML `name: dclh`，
`description` 声明简称触发场景。它覆盖整个插件，宿主按描述选择入口，再按任务读取技能。
自然语言匹配由宿主模型决定；需要显式选择时，各宿主的语法不同：

| 宿主 | 显式调用示例 |
|---|---|
| Codex | `$dclh 审计这个项目`（也可从技能选择器选择 `dclh`） |
| Claude Code 插件安装 | `/design-code-like-a-human:dclh 审计这个项目` |
| 其他 Agent Skills 宿主 | 从该宿主的技能选择器选择 `dclh`，以其实际语法为准 |

Claude Code 的插件技能使用 `插件名:技能名` 命名空间，因此这里不把 `/dclh`
声明为跨宿主命令。参见 [Codex Skills](https://learn.chatgpt.com/docs/build-skills)
和 [Claude Code Skills](https://code.claude.com/docs/en/skills)。

在 Codex 中，短入口转到 [using-design-code-in-codex](skills/using-design-code-in-codex/SKILL.md)，
原有长入口仍可使用；其他宿主直接选择下表的通用技能，不依赖 Codex 专有指令。
`plugin.json` 的插件名称用于安装标识，`interface.defaultPrompt` 只提供面板示例；
短入口由 `skills/dclh/SKILL.md` 定义。已安装旧版时，需要更新安装的插件并在新任务中
确认能找到 `dclh`；仅修改源码不会更新另一份已安装的缓存。

Codex 入口集中维护十项指令及配套操作：`/goal`、`/plan`、`/review`、`/diff`、`/ps`、
`/status`、`/compact`、`/resume`、`/fork`、`/permissions`。可用性以当前宿主为准。
已有适用的 goal 授权时直接使用；仅开启无人值守不会自动创建 goal。
通用技能继续维护实验流程，入口不启动第二套循环。

| 你在做什么 | 触发的技能 | 它做什么 |
|---|---|---|
| 让 Claude 写或改代码 | `writing-minimal-code` | 先查代码库里有没有现成的,再决定写不写 |
| 新项目、结构缺失或首次填 `layers` | `designing-project-layout` | 拟一份能直接写成 `layers` 的目录结构 |
| 写 Python 函数 | `writing-python-comments` | 按标准写 docstring:摘要 + 角色标记 + Args/Returns |
| 写会存文件的脚本 | `saving-experiment-outputs` | 动手前先说好输出存哪儿 |
| 开始、恢复或结束一组实验 | `running-experiments-on-branches` | 从固定基线开分支，人看过结果、说合并后用 `--no-ff` 合回实际目标 |
| 计划、运行或汇总实验 | `recording-experiment-results` | 跑前写计划，跑后补结果与版本关联 |
| 想看实验谁基于谁、探索到哪了 | `visualizing-experiment-lineage` | 从 CSV 和 git 画一页自顶向下的谱系图 |
| 功能跑通了想清理 | `auditing-code-comments` | 跑一遍审计,出一份报告 |

### 想主动触发就直接说

技能是按语义匹配的,用大白话就行:

    审计一下这个项目的代码

    这次实验的结果存哪儿?

    这组调参开个分支吧

    帮我把这个函数的注释补上

### 报告在哪

每次审计都在项目的 `.codegraph/` 下生成两份:

    .codegraph/audit.md      给人看,概览表 + 每条规则一张定位表
    .codegraph/audit.json    给 Claude 看,结构化数据

`audit.md` 可以直接打开。Claude 汇报时也会把路径给你。

### 手动跑(可选)

想脱离 Claude 自己跑,或者接进 CI:

    python3 <插件目录>/scripts/refresh.py <你的项目>

插件目录在 `~/.claude/plugins/cache/` 下,具体路径问 Claude 或者
`find ~/.claude/plugins -name refresh.py`。

退出码:**0 表示已执行的检查没有产出 finding**（带 `--base` 时只算本轮改动上的） —— 没建索引时四条图规则不跑,
这时的 0 不等于全部合规;1 有 finding;2 项目未启用、配置损坏或 `--base` 的 ref 不存在。

**不要单独运行 `codegraph sync`。** 它会把变动文件在索引里的记录整个删掉重建,
清空回填结果,注释会从索引里静默消失 —— 必须走上面这条命令。

## 实验的 Git 流程

一组实验一个分支，开组时记录固定的基线提交、合并目标和输出位置。
实验结束后补齐 CSV、选定最终实现与配置、完成审计和验证，再以 **`git merge --no-ff`**
合回项目约定的目标。这样目标分支新增一个有两个父提交的合并节点，具体尝试也保留在其历史中。
默认不使用 squash，也不通过 rebase 或 cherry-pick 代替合并。

- 项目直接以 `master` 为主分支：`实验分支 → master`；以 `main` 为主分支则合入 `main`。
- 项目明确使用集成分支：`实验分支 → develop → main/master`，每一级分别审阅、验证和合并。
  不为套模板额外创建 `develop`，也不随本组发布未授权的其他修改。
- 用 `git log --first-parent --oneline` 浏览目标分支的合并节点，用
  `git log --graph --oneline --all` 看详细历史。经过 `develop` 时，主分支节点可能汇集多组实验。
- 失败实验也保留记录；不保留的实现恢复到开组基线再合并。比较性扫描可以保留基线，不强行挑赢家。
- 合并后实验分支留不留由 agent 定，默认保留。合并、推送和输出备份分别验证；本地 stash 不随分支推送。

**改主分支的事要人来做，分支上的事 agent 自己控制。** 开分支、分支间合并、回退、删分支都不用等人；
到点只收尾到合并前一步（记录、收尾 commit、审计、验证、交接报告），合不合、合到哪由人看过结果后决定。
用户在场要求收尾合并且项目已明确合并约定时，收尾才包含本地合并。
已有推送授权则继续同步，未授权则交付本地可审阅结果。只要求暂停或保留分支时，不把它解释为完成合并。
完整命令、冲突处理、两父提交验证和恢复顺序以
[running-experiments-on-branches](skills/running-experiments-on-branches/SKILL.md) 为准。

## 接进你自己的实验循环

`program.md`（autoresearch）、ARIS 的工作流、项目自己的 `AGENTS.md`——这些是
**驱动层**，决定循环怎么走。本插件是它们下面的一层：提供检查，在你指定的位置跑，
不自己插进循环。

技能靠描述匹配触发，在自主循环里可能反复被唤起，也可能一次都不被唤起。
**可靠的接法是驱动层显式调用。** 把下面这段贴进你的驱动指令，放在
「改完代码、跑实验之前」那一步——那时工作区里就是这一次尝试的改动，
`--base HEAD` 正好把它们圈出来，而且写死的输出路径在烧 GPU 之前就能抓到。
以 autoresearch 为例，其他项目照改：

    每次改完代码、跑实验之前：
        python3 <插件目录>/scripts/refresh.py . --json --base HEAD
    只看 findings 里 changed=true 的条目——落在这次改动上的。
      D3（写盘路径写死了）  改掉再跑，否则输出会散落
      R1（零调用者）        先核对入口、动态引用和调用关系，确认是本次死代码且在授权范围内才处理
      R0（缺 docstring）    本项目不要求，忽略
      C1（改了函数没加变更行）调参改的就是函数默认值，每轮都会报，忽略；合并前以 --base <实际接收分支> 再认真看
      其余                   写进这一轮记录的备注，不阻塞
    带 --base 时退出码只看本轮，存量不算——但 C1 在调参时每轮都算 changed，所以退出码
    多半是 1，别拿它当「干净」的信号；看 changed=true 里除 C1 之外还有没有别的，没有就继续。
    退出码 2 = 审计没跑成，不是实验失败。记一笔，循环照常；连续几轮都是 2 就不再调审计，
    每轮记一句「审计不可用」，实验照跑——停的是审计不是循环。

处理哪几条、忽略哪几条是驱动层的决定，按项目改。`audit.json` 的字段见
`skills/auditing-code-comments/references/handling.md`。

**有没有外部驱动，接法不同。** 有 `program.md` 或 ARIS 那样的循环时，
把上面那段放进驱动指令。用户已授权无人值守后，按
[实验分支技能](skills/running-experiments-on-branches/SKILL.md) 先检查输出目录均被忽略，
再创建 `.codegraph/unattended` 标记；跳过忽略检查可能让输出进入提交或被 stash 收走。

没有外部驱动、只装了插件——`running-experiments-on-branches` 就是驱动，
你说「开始迭代」它自己落哨兵、自己跑循环、自己从压缩后恢复。
循环的每一步它**按名字调**对应的子技能（记录、写代码、写盘、审计），
和 ARIS 的驱动技能一样；子技能的 description 保留自动触发，作为没被点名时的兜底。
子技能在循环里每轮被调是设计，不是要消灭的重复触发。

**超时、重试、什么时候停，驱动层说了算。** `program.md` 里写了就按它的；
没写，`running-experiments-on-branches` 有一套照 autoresearch 抄的默认
（基线两倍超时、修两次放弃、开跑前查 CSV 去重）。默认是开放搜索：agent 自己规划、按趋势换方向，
跑到用户叫停或约定预算用完；用户明确给了固定清单的，清单跑完就停，不自行加项。
到点就清除标记、补齐记录并收尾到合并前一步；改主分支的事等人回来看过结果再做，分支上的操作自己控制。

**持续执行由宿主或外部驱动承担。** Codex 提供 goal 时，已授权的目标可跨轮次推进，
入口负责目标状态，通用技能负责实验步骤。没有原生 goal 或外部续跑驱动时，
当前轮次结束后不能保证自动继续；无人值守标记记录工作模式，本身不是调度器。

无人值守的具体处理见各通用技能（Python 注释标准不因模式而变）。共同边界如下：
**审计中的待定事项先记录，已授权的实验继续执行。** 不因存量 finding 自动修改项目声明、
删除文件或扩大实验范围；本轮代码按驱动约定处理，记录选择及理由。
缺少必需信息、授权或出现无法安全恢复的 Git 状态时，保留现场并汇报具体阻碍，不能把沉默当成同意。
`.codegraph/unattended` 存在且距修改不足 24 小时表示标记有效；`audit.json` 和 hook 提示
只是读取时的快照。标记不代替用户授权、运行状态或完成检查。

## 审计规则

| 规则 | 判定 | 来源 |
|---|---|---|
| R0 | 缺 docstring 或角色标记 | 读源码 |
| R1 | 零调用者(最外层与 `[一次性]` 豁免) | 索引 |
| R2 | `[一次性]` 不在最外层 | 索引 + `layers` |
| R3 | 主线调用旁支 | 索引 |
| R4 | `def` 那一行有的参数,Args 里没写 | 读源码 |
| R5 | 有 `return`/`yield` 值但缺 Returns/Yields | 读源码 |
| R6 | Args 里写了 `def` 那一行没有的参数 | 读源码 |
| D1 | 内层引用外层 | 索引 + `layers` 或 `vendored` |
| D2 | 输出区存在但未被 .gitignore 忽略 | 文件系统 |
| D3 | 写盘点写死了输出路径 | AST |
| C1 | 改了已有函数却没加 `变更:` 行 | 比 git |

R3、D1、C1 报出来时先判断再动手 —— R3 问「本次实验用得到它吗」，
D1 说「核心层依赖了脚本层」，C1 要分清改的是别人依赖的东西还是只动了内部。
它们和其余规则一样计入不合规、影响退出码,只是处置需要人的判断。
处置指引见 `skills/auditing-code-comments/SKILL.md`。

## 技能

| 技能 | 什么时候用 | 覆盖痛点 |
|---|---|---|
| `writing-minimal-code` | 写新代码或改既有代码前 | 1、2、5 |
| `writing-python-comments` | 写或改 Python 函数时 | 3、5 |
| `auditing-code-comments` | 功能跑通后、提交前 | 1、2、3 |
| `saving-experiment-outputs` | 写任何会写盘的脚本前 | 7 |
| `designing-project-layout` | 新项目、结构缺失、首次填 `layers` | 1 |
| `recording-experiment-results` | 实验计划、恢复、结果与总结 | 6 |
| `running-experiments-on-branches` | 实验开组、恢复、收尾与合并 | 6、8 |
| `visualizing-experiment-lineage` | 看方法探索的谱系：谁基于谁、哪条路死了 | 6 |

`writing-minimal-code` 是一条四道决策流：该不该存在 → 能不能改现有的 →
新写的话代码从哪来 → 写成什么样。

它的两个目标是让读代码的人负担最小、让改动总量最小，而这两件事经常被搞反：
为了「不动旧代码」不断新加函数和包装层，不是改动变小了，是换个地方堆着。
改动大小按 diff 算，不按碰没碰旧文件算。

它同时列出**不能为了简洁删掉**的几类代码：随机种子、train/test 边界、
数值稳定性处理、防数据丢失的错误处理。科研代码里一段看着多余的逻辑，
可能正是当初调出那个数的原因，删掉之后数变了还不报错。

后三个是习惯，不是流程：写盘前说好存哪儿、跑完先记再跑下一次、
实验别在主分支上跑。技能里给的目录形状、CSV 列名、分支命名都是模板，
项目有自己的习惯就跟着它走。

## 规范本身

**规范就写在技能里**,`skills/` 下每个 `SKILL.md` 都是可直接读的完整规则;
审计技能把启用指南和结果处置拆到了 `references/`,用到时再读。

每条机械规则背后都有一个 codegraph 的实测行为撑着,不是拍脑袋定的。
其中三条直接决定了工具的形状:

- codegraph 全语言统一读「前置注释」,**Python 的体内 docstring 捕获不到** ——
  所以要回填
- `sync` 会把整个文件在索引里的记录删掉重建,**回填的注释被清空,记录的编号也会变** ——
  所以不能旁挂 sidecar 表,只能每次重算
- 全文检索把连续的汉字当成一个整体、只能从头匹配，**中文关键词埋在词组中段就搜不到** ——
  所以摘要行要保留英文术语、关键词打头

设计文档、实施计划与调研笔记留在本地 `docs/`,不入库 —— 那是推演过程,
不是 plugin 的组成部分。

## 改规则之后

拿一个真实项目跑一遍,看漏报与误报:

    python3 scripts/refresh.py <项目>

规则里有几处不显眼的陷阱,改动时留意:

- SQLite 的 `LIKE` 中 `_` 是单字符通配符。过滤 `__init__` 这类名字必须写
  `NOT LIKE '\_\_%' ESCAPE '\'`,否则会滤掉**每一个**函数,规则静默失效
- `ast.walk` 会走进嵌套函数。判断"本函数有没有返回值"要自己走栈并跳过
  嵌套定义,否则内层的 `return` 会算到外层头上
- git 返回的是**仓库根**相对路径。项目根是仓库子目录时(monorepo)必须用
  `--relative` 与 `--show-prefix` 换算
- 目录匹配按路径段比,不按字符串前缀。`runs_archive/` 不算忽略了 `runs/`

## 警告：快速迭代模式会失控

`running-experiments-on-branches` 里的快速迭代模式——改、审、跑、差了 stash——
一夜能跑上百次。它的风险不是跑太少，是**搜索太激进**：agent 会死磕一个方向，
lr 推到 0.16 还在推；会在噪声里追假信号；会把整夜预算烧在一条早该放弃的路上。
每一步都是"合理的下一步"，合起来是盲目爬山。

插件对此的处理是**要求记录，不代替判断**：

- 什么时候放弃一个方向，agent 自己判断。技能里给的是判断依据——趋势、收益递减、
  有没有机制解释、剩余预算——没给硬数字。三次不改善是"该认真问"的时刻，不是开关。
- 放弃时**必须**把方向级结论写进 CSV 和 commit。这条没有商量。不写，下一夜的
  agent 会把同一条死路再走一遍。

跑一夜之前，把想试的方向和每个方向的预算写进你自己的驱动指令
（`program.md` 之类）。插件管"放弃了要留下记录"，不管"该不该放弃"。

快速迭代中，失败尝试的代码改动保存在本地 stash 中，分支合并和推送不会备份它们。
需要跨机器复现时使用代码提交或已约定的备份方式；不要把 stash 当作永久归档保证。
此前测试中，默认 `git gc` 后仍能找到
120 天前的 stash；显式执行 `reflog expire` 可使旧条目过期。stash 和 commit 一样保存
压缩快照：对一个 28 KB 的 `train.py` 保存 100 次，gc 后 `.git` 增加了 124 KB。
这是该次测试的结果，实际占用取决于保存的文件和改动量。

## 已知限制

- 只支持 Python。图规则(R1/R2/R3/D1)天然跨语言,读源码的那几条要为每种语言补解析器。
- codegraph 不跟踪 `import X as Y` 别名,只通过别名到达的函数会被 R1 误报。
- 模块级 docstring 不回填。
